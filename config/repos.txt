# 代码镜像仓清单 —— 「哪些仓」的唯一一份名单。
#
# 谁读它：
#   scripts/sync-mirrors.sh   服务器上跑，按这里的仓名 + 分支从 codeup fetch（本文件由
#                             scripts/install-cron.sh --server 一并 rsync 到服务器）
#   scripts/repos-apply.ts    把这份清单**播种**成 app_settings.code.mirror.repos
#   scripts/onboard-repos.ts  批量建镜像 + 索引 + 写 repo_coverage 的批量入口
#
# 为什么是一份纯文本而不是 shell 数组 / 又一份 JSON：
# 这一层要能被三处读到——Linux 上的 bash（没有 node）、本机的 tsx、以及人（加一个仓就是
# 加一行）。`REPOS=(a b c)` 只能被 bash 读，于是 TS 侧早晚会抄第二份，两份一漂，镜像同步
# 的和索引读的就不是同一批仓（2026-11-08 的 `123pan-cross-frontend` 正是这么漏掉的：
# 它在设置里、不在数组里，于是「代码快照较旧」挂了十几天没人知道）。
#
# 格式：<仓名><TAB 或空格><分支>；`#` 开头整行是注释；空行忽略。
#   - 仓名只放行 [A-Za-z0-9._-]：它会被拼成服务器上的路径
#     （/srv/123pan-mirror/<仓名>.git），带 `/` 或 `..` 就是一次路径穿越。
#   - 分支写**远端真实存在的那一个**。镜像的 HEAD 会跟着它走，而 `head()` 读的是 HEAD
#     ——分支写错时出错方式是「读到了另一个分支的最新提交」，不是报错。
#   - 顺序无意义；合并去重按仓名，重名直接报错（早失败比跑到一半更像一件事）。
#
# 加一个仓的顺序（两步，第二步是幂等的）：
#   1. 在这里加一行 → commit
#   2. scripts/repos-apply.ts --dry-run（看 diff）→ scripts/repos-apply.ts
#      再 scripts/onboard-repos.ts（建镜像 + 索引 + 覆盖率）
#   服务器上的镜像同步不需要再改：它读的就是这份文件。
#
# 前三个是本产品已知的前端/前端配套；agent-tracker 与 gateway 是 2026-11-08 owner 点名的
# 两个仓（原先只存在于口头清单里，没有镜像）。
