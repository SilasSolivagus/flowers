# 代码镜像仓清单 —— 「哪些仓」的唯一一份名单。
#
# 谁读它：
#   scripts/sync-mirrors.sh   服务器上跑，按这里的「仓名 + 分支 + path」从 codeup fetch
#                             （本文件由 scripts/install-cron.sh --server 一并 rsync 到服务器）
#   scripts/repos-apply.ts    把这份清单**播种**成 app_settings.code.mirror.repos
#   scripts/onboard-repos.ts  批量建镜像 + 索引 + 写 repo_coverage 的批量入口
#   src/core/codemirror/repo-inventory.ts  解析器（TS 侧唯一一份）
#
# 为什么是一份纯文本而不是 shell 数组 / 又一份 JSON：
# 这一层要能被三处读到——Linux 上的 bash（没有 node）、本机的 tsx、以及人（加一个仓就是
# 加一行）。`REPOS=(a b c)` 只能被 bash 读，于是 TS 侧早晚会抄第二份，两份一漂，镜像同步
# 的和索引读的就不是同一批仓（2026-11-08 的 `123pan-cross-frontend` 正是这么漏掉的：
# 它在设置里、不在数组里，于是「代码快照较旧」挂了十几天没人知道）。
#
# ─── 格式（2026-11-09 起：多了 path= 一格）────────────────────────────────────
#
#   <仓名><空白><分支>[<空白>path=<组路径>][<空白>stale=<天数>|never]
#
#   `#` 开头整行是注释；空行忽略；一行坏了整份作废（半份仓库列表比没有更糟）。
#
#   path=   组织相对的**克隆路径**，含仓名：`123pan/apisrv`、`cdn-groups/beats`、
#           `apisrv`（组织根）。克隆地址 = CODEUP_ORG + `/` + path + `.git`，
#           只在 `src/core/codemirror/repo-inventory.ts` 的 `cloneUrlOf()` 一处拼。
#           缺省（不写）= `123pan/<仓名>`，那是 2026-11-09 之前唯一存在过的地址，
#           旧清单逐行读出来仍然指向原来那个仓。
#   stale=  超过这么多天没有新提交才提醒（缺省 7）；never = 上游已归档/停更，
#           不因「上游不动了」提醒，**但同步失败照样报**。判定在 health.ts。
#           第三格光着写 `never` / 正整数仍然按 stale 读（历史写法）。
#
# 三条校验（`parseRepoInventory()` 与 shell 侧逐条对齐）：
#   1. 仓名只放行 [A-Za-z0-9._-]：它会被拼成服务器上的路径
#      （/srv/123pan-mirror/<仓名>.git），带 `/` 或 `..` 就是一次路径穿越。
#   2. path 的最后一段**必须等于仓名**：镜像目录按仓名建、克隆地址按 path 拼，
#      两者不一致时错法是安静的（目录里躺着 A 仓，每晚去 fetch B 仓）。
#   3. 重名是错误。同一个仓名在 codeup 的两个组下各有一份时只能收一份，
#      另一份写进 `config/repos-excluded.txt`（那里记「为什么不要它」）。
#
# ─── 为什么多了 path= 这一格（2026-11-09，34 个仓「不存在」的真正原因）────────
#
# 克隆地址原来是**拼**的：`…/60f9058e68e2993a8e6d0750/123pan/<仓名>.git`。这个拼法把
# 「仓在哪个组」写死成了 `123pan`。而 `ListRepositories`（`x-total: 144`）的真实返回里，
# **多数仓就在组织根**（`…/artifacts.git`）、少数在 `123pan/`、`cdn-groups/`、`test-groups/`。
# 于是 `…/123pan/artifacts.git` 被远端答成「未知的仓库路径，请检查仓库路径是否正确」——
# 一句听起来像「这个仓不存在」的话，`repo_coverage.error` 也就照抄成了「不存在」。
# 那 26 个「不存在」不是现实，是我们问错了地址。组路径是**仓的属性**，只能从清单里读。
#
# 镜像目录名**不改**：仍然是裸仓名（/srv/123pan-mirror/<仓名>.git），66 个已有镜像一个都
# 没动过，改的只是 fetch/clone 用的地址。这样「改名 66 个目录 + 改 66 行设置」的风险
# （漏一个就是一次静默的换仓）全都不存在，而 path 已经承担了「地址从哪来」这件事。
#
# ─── 加一个仓的顺序（第二步是幂等的）────────────────────────────────────────
#
#   1. 在这里加一行（path 从 `ListRepositories` 的 pathWithNamespace 抄，别自己拼）→ commit
#   2. npx tsx scripts/repos-apply.ts --dry-run（看 diff）→ scripts/repos-apply.ts
#      再 npx tsx scripts/onboard-repos.ts（建镜像 + 索引 + 覆盖率）
#   服务器上的镜像同步不需要再改：它读的就是这份文件。
#
# 分支一律**逐个 ls-remote 验过**（2026-11-09，144 个 path 全跑了一遍）：绝大多数是
# master，另有 main / dev / v1 / lighthouse_v1。分支写错的错法是安静的——fetch 成功、
# HEAD 很新、材料对着另一个分支的代码。

# ─── 按仓的 stale 阈值（判据只有一条：**这个仓多久没有任何提交是正常的**）─────
#   virtuallist-antd  never   2023-06-04 之后再无提交（1254 天）。已归档的组件库，HEAD
#                             年龄不是关于我们管道的任何事实；任何有限数字早晚会被跨过，
#                             然后下一个人会看到一个「阈值」并以为它是量出来的。
#   review            never   codeup 上 archived=true，最后活动 2021-08-19。**归档不等于不
#                             存在**，所以它仍然在清单里、仍然被索引；只是不该因为它不动
#                             而每晚提醒。
#   ele-react         730     停更的 Electron 客户端（364 天）。留一条硬上界。
#   share             540     分享页（339 天）。产品仓，只是发版稀疏。
#   eslint-config     365     配置库（161 天）。按年改一次是它的正常节奏。
#   agent-tracker     365     内部工具（73 天）。季度级改动。
#   gateway           180     网关（50 天）。活跃组件，半年是上界。
# 这七个之外**一律不写这一格**（= 全局 7 天）：给所有仓放宽阈值等于把这一列取消掉。
