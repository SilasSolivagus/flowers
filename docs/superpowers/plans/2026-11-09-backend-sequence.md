## 1. 节点分类学

一个流程节点现在是**两类三态**，判据写在 `inspect.ts` 的 `verifyPrompt` 与
`compose.ts` 的 `fragmentsPrompt` 里，落到数据上是 `PageFragment` 的一个字段差：

| 节点形态 | 它是什么 | 必须交什么 | 拼装之后 |
| --- | --- | --- | --- |
| `kind=page` | 用户在某一屏上做的事 | `frame` + `html`（`wt-*` 片段） | 页面 `p-<节点id>`，进 `.frame-phone` / `.frame-wide` |
| `kind=system` | 服务端自己做的事（发放、记账、回调、重试） | `steps`：`{from, to, what}` 有序数组 | 伪页面 `backend-<节点id>`，`frame=sequence`，进 `.frame-seq` |
| `kind=decision` | 服务端的一个判断 | 同 `system` | 同 `system` |

为什么 `decision` 也算后端：判断发生在服务端，它没有用户界面。**「判断」与「页面」不是
一对反义词**——这一步原来被当成「挂在相邻页面上的旁注」，纯后端流程里就没有相邻页面可挂。

兜底（老行为，**已在第三轮删掉**，见 §9.1）：`system` / `decision` 没交 `steps` 时，原来仍挂到
最近的页面节点（前一个，没有就看后一个），理由是「旧材料不许因为这次改动变样」。那条理由在
第三轮被推翻：兜底产出的是一句假陈述（读者以为那一步有界面），所以现在**判为后端却没有步骤
的节点整份退回**，不再挂页面。旧材料是磁盘上的静态 HTML，不会被重新生成，因此照样能看。

## 2. 参与方词表：**封闭**，且必须是产品级

`src/core/uemaster/sequence.ts` 是唯一的事实源：

```
用户 / 页面 / 运营后台 / 服务端 / 支付渠道 / 通知渠道 / 第三方
```

判据是「PM 会不会用这个词跟研发说话」：

- **用户**：产品的人；
- **页面**：用户眼前的那一屏（含弹窗）；**运营后台**单独一列，因为责任不同（运营操作 vs 用户操作）；
- **服务端**：产品自己的处理（算钱、记账、发权益）——**不写**哪个服务、哪个类；
- **支付渠道 / 通知渠道**：两个必然穿过产品边界的环节，分开是因为「钱退了但没通知到人」与
  「通知发了但钱没到」是两类事故；
- **第三方**：其余外部系统（物流、发票平台、外部订单来源）。

**为什么封闭**（三条，缺一条都会重新长草）：

1. **封闭才可判**：`normalizeSteps` 能对每一个参与方说「这个词不在词表里，只能用这七个」，
   而不是「看起来像代码，也许不行」——后者模型永远改不对。
2. **封闭才可排**：列宽、折行、字号全部按「最多 7 列」算过（§3）。开放词表意味着列宽无界，
   6 列就会挤成一条线。
3. **封闭才不漂**：十份材料里读者看到的是同一套角色名。这是 owner 那条规矩
   （`body-language.ts` 两轮清词）能站住的前提。

同义写法收进别名表（`客户端→页面`、`后端→服务端`、`短信→通知渠道`…），因为那是模型的
正确直觉换了名字；**表外的名字一律报错**——那才是「它自己编了一个角色」。

`what` 这一格是自己的判据（`STEP_PATTERNS` + `hasProseLeak(what,'gap')`）：

| 出现的形状 | 报的话 |
| --- | --- |
| `ShareController.refund()` | 这一步里出现了方法调用「…」 |
| `RefundService` / `RefundDao` | 代码类名 |
| `select … from t_order` | SQL 语句 |
| `t_refund_order` / `refund_status` | 表名或字段名（下划线命名） |
| `POST /api/refund` | 接口地址或 HTTP 动词 |
| `退款金额计算()` | 空括号（函数调用的形状） |
| `带 focus 参数跳…` | 实现词（`gap` 档：参数/字段/接口/埋点无豁免） |

步数上限 12、单步 ≤28 字：超了不是「画不下」，而是**模型在一句话里塞了两个动作**，
该拆成两步（28 字正好是 11px 两行的容量，见 §3）。

## 3. 渲染器：确定性 SVG（零依赖、无 mermaid 运行时）

`sequenceSvg(steps)` → 一张 `<svg viewBox="0 0 690 H">`。同一份步骤在任何机器上排出**同一份
字节**（有断言），所以它可以进 `pages[]` 被 `build.py` 原样搬进产物。

### 排版规则

| 项 | 规则 | 为什么 |
| --- | --- | --- |
| 宽度 | 固定 690px（= 模板 `.frame-wide` 的宽），`width/height` 都写死，CSS 只做 `width:100%` | 跟容器走会失去确定性，测试就无法逐字断言 |
| 列 | 参与方按**首次出现**顺序均分宽度，列心 `PAD + colW*(i+0.5)`，两侧各 16px | 顺序稳定 → 同一份步骤永远同一张图 |
| 参与方框 | 高 26px、宽 `min(colW-12, 160)`，圆角 6，文字居中（放不下先缩字号再省略） | 名字是 2–5 个字，够 |
| 生命线 | 虚线 `3 4`，从框底到画布底 -6 | 与消息箭头区分 |
| 消息 | 一行一条，编号 `N. `，标签框宽 `min(658, max(箭头跨度, 240))`，居中于箭头中点并**夹在边距内** | 相邻两列之间的箭头只有 94–164px，标签因此向两侧借空间，不会挤成三行 |
| 折行 | 逐字符贪心，中文按 1em、半角按 0.56em 估宽；**最多两行** | 不做字体度量：确定性优先 |
| 省略 | 超两行 → 第二行末尾加 `…`，`layout.elided` 记账 | 缺字在结尾，读者知道后面还有 |
| 自环 | `from === to` 时画右出、下折、回指的回勾（22px），标签靠右 | 零长度箭头会画成一个点 |
| 行高 | `折行数 × 14 + 8`（自环再 +12） | 高度只由内容决定，没有随机量 |
| 颜色 | 图里只写类名（`.seq-box` / `.seq-arrow` / `.seq-msg` …），颜色在模板 CSS 里走 `--wt-*` 变量 | 深色模式跟着模板走，不用塞第二套颜色 |

### 极限（实测，不是估计）

| 参与方 | 单条消息可用宽 | 每行字数 | 结论 |
| --- | --- | --- | --- |
| 1–2 | 329–658px | 30–59 | 干净：标签框比列距窄 |
| 3 | 219px | 21 | 勉强：240px 的标签框比列距宽 21px，偶尔压到生命线 |
| 4 | 164px | 21 | 标签框明显跨过一条生命线，但每条消息独占一行，读得下去 |
| 5–7 | 94–132px | 21 | 同一行里标签会跨过 2–4 条生命线；图仍可读，但已经**不能算排版漂亮** |
| ≥8 | — | — | 不可能：词表只有 7 个角色 |

- **消息数**：上限 12（`MAX_STEPS`）。实测高度：4 步 210–226px、6 步 278px、12 步 466–620px
  （690px 宽那一栏可以上下滚，视觉上还在一屏之内）。
- **什么时候开始丢字**：`elided` 只在「两行放不下」时 >0。合同内（≤28 字、≤12 步、
  ≤7 列）实测 **0/12 被省略**——240px 的标签框容得下 21 字/行 × 2 行 = 42 字 > 28 字上限。
  换句话说省略号是**安全网**（有人绕过提示词写长句时兜住），不是日常路径。
- **两份真实材料的实际丢弃量**：`elided = 0`。发生过一次**折行**（`PAN-815` 的 F 节点
  「4. 发到企业微信客服群」折成两行），没有省略。

## 5. `validateWalkmap` 的规则改动

### 改了什么

1. **`Frame` 多了第三种取值**：`phone | wide | sequence`。`pages[]` 的条目可以带
   `kind: 'sequence'`。为什么是新的 frame 而不是复用 `wide`：`wide` 在模板里是「浏览器窗口」
   （白底、边框、地址栏那一族样式），把一张图塞进去会被读成页面。
2. **时序图那一格换了判据**（第 7 条）：`wt-*` 组件类**不查**（SVG 图里一个都没有，
   查它就是要求「图里得有手机框」），改查两条：
   - 片段里有 `<svg` → 否则 `节点页面 backend-X 的后端流程图没有画出来（片段里没有 SVG）`；
   - 片段里有至少一个 `seq-actor` → 否则 `…的后端流程图里没有参与方（至少要有一个「谁 → 谁」的角色）`。
   这两条盯的是「伪页面建了、内容是空的」——节点点开一片白，比整份拒收更难发现。
3. **拒收那句话换了中文**（第 4 条，判据本身**一字不让**）：

   ```
   节点 Z 既没有页面也没有后端流程：要么它落在一张页面上（给 html 与 frame），
   要么它是一组服务端步骤（给 steps：谁 → 谁 · 做什么）；现在是「p-不存在」
   ```

   旧的 `节点 Z 没有对应的页面（引用了不存在的页面「空」）` 不再出现：它只说「空」，
   读的人不知道下一步该给什么。**守门人还在**——这是 `PAN-815` 那次事故唯一能拦住
   「材料静默少一步」的判据。

### 什么仍然被拒（一个都不放松）

- 节点既没页面也没 `steps` → 上面那句话（含真实原因：现在指的页面 id）；
- 页面片段没有 `wt-*` 类 / 含 emoji / 是整份文档 / 用了 emoji；
- 状态组只剩一个状态、代表节点不存在、`state` 归属不对；
- `default_node` 不在映射里；
- 时序伪页面的片段是空的；
- 时序列里的问题（参与方不在词表、`what` 里有代码形状、超 12 步 / 28 字）在**读回话那一层**
  就退回，报 `节点 X 的第 2 步：…`。

## 6. 仍然做不到的（具体，不含「未来可优化」）

1. **genuinely neither 的节点没有出路**：一个既不是页面、也不是服务端动作的步骤（比如
   「第三方自己内部怎么处理」「线下谁去搬货」）现在只有两条坏路——硬编一张页面，或者硬写
   两组参与方。它会以「既没有页面也没有后端流程」被拒，而**正确的做法是把它从流程图里删掉**
   （它不属于我们产品的流程）。→ **已在 §9.2 关掉**（提示词让模型删、删了说一行，拒收留作兜底）。
2. **词表是产品判断，不是自动的**：加一个角色（比如「资金账户」「客服人员」）要同时改
   `PARTICIPANTS`、`ALIASES`、一条用例，还要重算列宽。我**没有**为了让某条需求好看而加角色。
3. **省略号是安全网**：5–7 列时标签框仍会跨生命线。真正的排版解是「超过 4 列就折成两段图」，
   那是另一个设计，这次没做（也不该在没人要求时做）。
4. **`decision` 与 `system` 在图上长得一模一样**：两者都是「服务端参与方」的列。评审分不出
   「这是一个判断，还是一个动作」——它在流程图里分得出（菱形 vs 双边线），在时序图里分不出。
5. **没有状态组**：时序图不参与「页面状态切换」。这是对的（后端步骤没有「态」），但如果
   某条需求真的用「服务端的三种处理态」讲故事，材料里表达不出来。
6. **`build.py` 现在多认一个 frame**：上游升级时这两块补丁必须手贴回去（见
   `vendor/uemaster/README.md` 的「本地补丁二」与 `tests/walkmap.test.ts` 的 `LOCAL_PATCHES`
   那张剥除表）。忘贴的后果不是崩，是**时序图安静地不出现**（`page_divs` 过滤掉第三种 frame）
   ——所以补丁里那句话写了「静默丢是这里最坏的失败方式」。

## 9. 第三轮：两个缺口收口（2026-11-09 同日）

§1 的兜底（`system` / `decision` 没交 `steps` → 挂到最近的页面节点）与 §6.1 的
「genuinely neither 的节点没有出路」在这一轮一起关掉。两条规则，一句话概括：

> **判为后端就必须说清它在服务端做什么；既看不见也不在服务端发生的步骤，不属于产品流程。**

### 9.1 规则 A：判为后端却没有步骤 → 整份拒收（兜底删掉）

三处改动，缺一条规则就只在一处成立：

| 位置 | 改了什么 | 为什么是这里 |
| --- | --- | --- |
| `compose.ts` · `readFragments` | `kind !== 'page'` 且 `steps` 为空/缺 → `missingStepsReason(...)` 整份退回 | 这一层看得见 `kind`，能说「你判它是服务端的事，就说明它做了什么」 |
| `inspect.ts` · `readVerify` | 同上（同一句措辞，`sequence.ts` 是唯一来源） | 走查那条路与评估/评审那条路各有一个读回话的口，两处必须同一句话 |
| `compose.ts` · `assembleWalkmap` | **删掉**「挂最近的页面节点」那条兜底（连同 `Assembly.detached` / `nearestPage`） | 兜底产出的是一句假陈述：一步服务端的事，读者看见的是一屏界面 |

实测的运维原话（`composeEvaluation` 打出来的整句，第二条是真跑一次强制失败路径的输出）：

```
页面片段 2 次都没通过校验：节点「A 接收回调」判为后端流程但没有给出步骤：请说明这一步在服务端做什么（给 steps：「谁 → 谁 · 做什么」，1–12 步，每步 ≤28 字）
```

内嵌的那一句（`missingStepsReason(id, title)`，逐字）：

```
节点「<节点id> <节点标题>」判为后端流程但没有给出步骤：请说明这一步在服务端做什么（给 steps：「谁 → 谁 · 做什么」，1–12 步，每步 ≤28 字）
```

**两句不合并**（这是 owner 那句「别把两件事说成一句」的具体落法）：

| 谁在说 | 说什么 | 说的是什么 |
| --- | --- | --- |
| `readFragments` / `readVerify` | 判为后端流程但没有给出步骤 | **意图与义务**：你判它是服务端的事，那就要说明它在服务端做什么 |
| `validateWalkmap` 第 4 条 | 既没有页面也没有后端流程 | **事实**：这个节点没有落点（契约里没有 `kind`，这一层看不见模型的意图） |

迁移口径：**只有生成变严格**。旧材料在磁盘上是静态 HTML（`<data>/uemaster/PAN-*/**.html`），
没有任何代码会重新读一遍再判它合不合格——它们照样能打开、照样点得动。变化只发生在
「下一次生成」：模型不交步骤，这一份就出不来，而不是安静地少一句真话。

### 9.2 规则 B：既不是页面、也不是服务端动作的步骤 → 从流程里删掉，删了说一行

提示词里的那一段（`compose.ts` 的 `FLOW_DROP_RULE`，逐字；`flowPrompt`、`repairPrompt`、
`structurePrompt`、`structureRepairPrompt` 四条流程提示词都贴同一份）：

```
不属于产品流程的步骤不要画：一个步骤如果既不是用户在界面上能看到的，也不是服务端会做的事
（例如「第三方自己内部怎么处理」「线下谁去搬货」「开会评审这件事本身」），把它从图里去掉。
硬画成页面或硬写成服务端动作，读者会以为那一步真的这样发生。
去掉之后在最后单独一行写「已删去：<原步骤文案>」——删了却不说，读者会以为材料漏了一步；
一个都没去掉就什么都不要写（这一行不是必填）。
```

「说一行」不是许愿：`droppedNotesIn` 只认整行以「已删去 / 已去掉 / 已略去」+ 冒号开头的
形状（节点文案里出现同名词、句子中间的提及都不算），`buildFlow` 把被接受那一版的清单交出来，
`reportDropped` 打一行：

```
[flow-drop] PAN-815 inspect 已删去 1 个不属于产品流程的步骤：线下谁去搬货
```

**拒收是兜底，没有撤**：模型无视这段提示词、把这种步骤硬画成页面或硬写一组参与方时，
规则 A（判为后端没给步骤）与 `validateWalkmap` 第 4 条（既没有页面也没有后端流程）仍会让
整份失败——宁可整份失败，也不静默漏一步或静默编一步。

### 9.6 仍然粗糙的地方

1. **删除清单只到日志**：`[flow-drop]` 这一行在 stderr 与 `buildFlow` 的返回值里，材料正文里
