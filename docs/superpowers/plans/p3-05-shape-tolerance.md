# 形状容错：从「一条一条撞」到「一轮跑完收干净」

目标：让 Flowers 对任意 LLM 的回话形状容错做到**穷尽且可证**——不是"我觉得够了"，是**新一轮真实采样不再出现未覆盖的漂移**。

## 为什么这件事本身是个问题

模型回话的形状漂移**一次只暴露一处**，因为 zod 只报第一个 issue，而一轮真实生成要 1–4 分钟。以前的节奏是：

```
真实跑 → 报一种漂移 → 改一处 → 真实跑 → 报另一种 → …
```

六轮之后才凑齐九种。这套办法既慢又不可能"穷尽"——你不知道还剩几种。

## 办法：先把语料拿够，再一次性收

`scripts/shape-corpus.ts`（常驻工具，永久的）：

```bash
npx tsx scripts/shape-corpus.ts \
  --requirements 1,2,6,7,10 --stages evaluate,review,inspect \
  --models deepseek-flash,deepseek-v4-pro --repeat 3 --concurrency 4
```

四个设计决定，每一个都对应一次踩过的坑：

| 决定 | 为什么 |
|---|---|
| **一次收全部 zod issues**，不是第一个 | 一个回话里常同时有 2–3 种漂移；只看第一个等于把一次调用浪费掉 |
| **原始回话先落盘再解析** | 批次中途挂了语料还在，不用重跑 |
| **每格重复 ≥2 次** | 漂移不是确定性的，1/3 概率的形状跑一次看不见 |
| **`--rescan` / `--report-only`** | 报告是渲染，语料是事实；改了容错能零成本重判 |

跑批的预算常量与应用保持一致（`flow 12k / pages 24k / structure 32k / verify 64k`）——这一点曾经不一致，导致跑批复现出**产品里已经不存在的**截断，差点被读成"还有 11 处漂移"。

## 两轮语料

| 轮次 | 需求 | 调用 | 通过 | 被拒 | **未知形状** |
|---|---|---|---|---|---|
| 一 | 1,2,6,7,10（含旧需求） | 132 | 115 | 16 | **0** |
| 二 | **3,4,5,8,9,11,12（全新）** | 112 | 92 | 18 | **0** |

第二轮是验收：用的全是第一轮没碰过的需求。**112 份回话里没有一种形状落进未覆盖的分支。**

第二轮那 18 条被拒的构成：

```
12 条  撞 14000 预算被截断   ← 跑批进程加载的是旧常量（产品已是 24k）
 6 条  模型漏了节点 G/H      ← 语义错误，本来就该拒
```

## 收进容错层的九种漂移

每一种都有模型原文，测试是表驱动的（`tests/shape.test.ts`，34 条）。

| # | 漂移 | 观测次数 | 收法 |
|---|---|---|---|
| 1 | `verdict: "missing/缺失"`、`"partial/部分实现"`、`["inconsistent/不一致"]` | 13 种写法 | 别名表 + 整句子串兜底 + 数组取首 |
| 2 | `anno: ["一致","说明"]`（少一层数组） | 多次 | 成对还原 |
| 3 | `frame: "分享页浏览"`（写成人话） | — | 关键词归类，默认 phone |
| 4 | `kind: "判断"` / `"系统"` | — | 同上 |
| 5 | `evidence: ["repo:path"]`、`{file:"repo:path"}` | 68 + 30 | 按**值**认仓库前缀，不猜字段名 |
| 6 | **一条字符串里拼了 2–3 份证据** | **30** | 按顿号/逗号/换行切开逐段扶正 |
| 7 | `searched: true`（布尔） | 48 | 丢掉这一格 |
| 8 | 节点漏写 `title` | 2 | 用 id 补（id 是唯一标识） |
| 9 | `repo` 空 / 路径只在一个仓里 | 1 | 拿两个仓的 `lsTree` 反查，唯一命中才补 |

另外三处不属于"形状"但同样在浪费调用：

- **截断单列**：`extractJson` 在截断的 JSON 里会退到内层配对对象，报成「缺 nodes」。现在解析前先判括号配平，措辞直指「把 max_tokens 调大」。
- **链式 mermaid**：`A --> B --> C` 是合法 mermaid，但排版引擎只认一行一条边。拆开是等价改写。实测：原样喂引擎被拒，拆开后 `crossings=0 overlaps=0`。
- **图里不存在的节点**：挂不到任何流程节点上，零信息，直接丢；覆盖率检查照常。

## 一个我自己造成的错误（值得单独记）

第 6 条之前，我的容错**只取字符串里的第一个路径**。模型把三个**真实存在**的文件拼成一条字符串，于是我报「路径不存在」——**容错把真话判成了假话**。

语料把它抓出来了。这说明了容错的危险面：写错一个 `slice(0,1)`，比不写容错更糟，因为它会让系统用自信的语气拒绝正确的东西。

同理还有一次：我把「`missing` 不许带证据路径」定成硬规则，而真实世界里缺失几乎总有"它本该在的那个文件"。模型因此被拒了一整轮。规则改成：允许带，但必须说清搜了什么。

## 截断为什么是预算不是容错（实证）

拿第二轮那 15 条撞顶的 prompt，按 `max_tokens=24000` 重打 3 条：

```
deepseek-flash-evaluate-12-1-pages: 通过  completion=14586
deepseek-flash-evaluate-4-1-pages : 通过  completion=17261
deepseek-flash-evaluate-4-2-pages : 通过  completion=19392
```

三条的 completion 都超过旧的 14000 上限，全部通过。**证明那 12 条是常量旧了，不是解析能力不够。**

## 没能自然触发的形状（诚实清单）

以下 9 种我**手工构造**过并有测试，但在 244 次真实调用里**没有自然出现**，所以不能算"实测覆盖"：

`frame` 写成中文、`anno` 写成对象行、节点无 html、`{file,note}` 形状、`root` 是数组、`subgraph`、`missing` 既无证据也无 searched、`kind` 别名、顶层多键。

它们由 `tests/shape.test.ts` 兜着，但下一次换模型（尤其非 DeepSeek）时应当**重跑一遍语料**，把它们从"没触发"变成"触发了也收得住"。

## 结论

**验收标准已达成**：112 份来自全新需求的真实回话，零未覆盖形状。

容错层的边界要说清楚：它只放宽**表达形状**，不放宽**事实**。路径是否存在、`missing` 是否自相矛盾、节点覆盖是否完整——这些仍然硬拒，因为那才是材料的价值所在。

新接一个模型时的动作：`npm run seed -- --reset` → 恢复 `provider.*` → 跑一轮 `shape-corpus` → 看 `report.md` 里有没有"未知形状"。有就补，没有就换下一个模型。
