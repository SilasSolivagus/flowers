## 1. 词表：六类，每类一条误伤护栏（`src/core/uemaster/body-language.ts`）

加一类的门槛是回答两个问题：**它为什么一定让 PM 翻页**、**哪些正常中文会被它误伤**。
答不出第二个不加——误伤不会被抱怨，它只会让句子悄悄变短。

| 类 | 判据（正则/上下文） | 为什么算违规 | 误伤护栏 | 护栏用例（必须活下来） |
| --- | --- | --- | --- | --- |
| `query` 网址参数 | `[?&]字母…=` | 「参数名」是地址栏里的东西，不告诉用户看到什么 | **必须带 `=`**；`#node=节点id` 这种锚点不以 `?`/`&` 开头 | `支持 #node=节点id 直达。` |
| `status` 状态码 | `302/301/307/400/403/404/500/502/503` | 「302 到新页」的产品说法是「旧入口自动跳到新页面」 | ①只在挨着 跳/返回/状态/页面/错误/重定向/入口 时拦；②`3xx + 到 + 页面词` 单独一条；③后面跟量词（个/元/天/年/折…）一律不拦 | `2026 年 3 月上线`、`预计影响 302 个用户`、`302 到 500 个用户`、`这一版页面多了 302 个会员`、`0.97 元/天` |
| `identifier` 裸驼峰/蛇形大写 | `purchaseRecord`、`ORDER_ID`（**无**反引号） | 模型/字段的内部名字，读者认不出它是什么 | 品牌白名单 `PROTECTED_WORDS`（`iCloud`/`iPhone`/`iPad` 与 `purchaseRecord` **同形**，不列就会被当驼峰删掉）；首字母大写的单词（`Share`）与全大写无下划线（`VIP`/`SKU`/`API`）不匹配 | `备份走 iCloud，iPhone 和 iPad 上都能看。`、`SVIP 月卡…走 iOS 内购，WiFi…`、`SKU 编号与 API 调用额度` |
| `extension` 裸扩展名 | `.vue/.ts/.tsx/.jsx/.js/.mjs/.cjs/.json/.go` | `.tsx` 对读者是零信息 | **前面必须是字母开头的词**（`0.97`/`v1.2.3`/`2026.11.09` 以数字开头，不吃） | `按 0.97 元/天折价，v1.2.3 版本上线` |
| `impl-noun` 实现名词 | 字段/接口/埋点/参数/路由/组件/接口地址/入参/出参 | 「字段」不说是哪个信息项，「埋点」不说统计什么 | ①`接口` 在**正文档**放过「第三方/开放/对外/合作方接口」（那是「要不要备案」的领域说法）；②`路由器` 是硬件；③**「分页」「导出」「排序」「筛选」不在词表里**——它们是需求自己的领域词 | `列表底部加分页，导出按钮放右上角，表头点了能排序、能筛选。`、`第三方接口要备案…`（正文 0 处；缺口档 1 处）、`路由器需要重启一次` |
| `impl-noun` 代码变量名（只在缺口档） | 封闭表：`tab/tabs/focus/param/params` | owner 那段话里的 `tab`/`focus` 就是这类 | **不做成「所有英文单词」**：`PRD`/`App`/`H5`/`UI` 都是正文里的正常词。表里一个词加一行 + 一条用例 | 同上（`VIP`/`iOS`/`WiFi`/`SKU`/`API` 全部不拦） |

## 2. 两档严格度：`body` 与 `gap`

「缺口 / 建议」是 PM 拍板的地方，那里出现实现词等于这一条没写成结论；而「分页」「导出」
本身就是需求自己的领域词，出现在正文里是对的。所以给 `findProseLeaks(text, mode)` 两个档：

- `gap`：缺口 / 建议 / 风险 —— 实现名词**一律**算违规，代码变量名也算；
- `body`：其余正文（页面文案、verdict 行）—— 实现名词只在**不构成领域词**时才拦。

**谁算 `gap`**：标注里除 verdict（一致/缺失/多余/不一致）之外的每一行，以及评审问题清单的 `why`。
判据落在 `sanitizeAnno`，verdict 集合是 `body-language.ts` 的 `VERDICT_ROW_TITLES`，
与 `inspect.ts` 的 `VERDICT_NOUN` **用一条用例钉住**（`VERDICT_ROW_TITLES` vs `Object.values(VERDICT_NOUN)`，
防止两边漂——漂的方向一定是「缺口里的词被按正文放过了」）。

## 3. 改写 vs 搬走：**先改写，改不了才搬**

第一轮只有「搬」（删整句、原句进脚注），对路径是对的，对**词**不对：`302` 的正文版本是
「自动跳转」，删掉整句等于把一句产品上的话也删了。所以这一轮：

1. **改写**（句子留在正文）：只替换**含义与输入无关**的记号——
   状态码→`自动跳转/打不开/出错`；扩展名→删；查询串→`（带上定位信息）`；
   实现名词→`信息项/系统对接/数据统计/设置项/页面跳转/页面模块/提交的内容/返回的内容/对接地址`；
   页面语境的裸驼峰→`该页面`；缺口档的 `tab/focus`→`标签/定位`。
   换掉这些词不改变一句话说的是什么，**信息零损失**。
2. **搬走**（整子句进末尾「研发参考」）：**命名类**记号——`路径:行号`、带目录路径、
   反引号标识符、**非页面语境**的裸驼峰。它们指着具体一个东西（哪个文件、哪一项、哪条订单），
   机械替换必然丢信息；读懂需求才能重写，那是提示词的活，不是正则的活。
3. **判据是机器能判的那一条**：`rewriteClause` 先看有没有命名类记号（有就直接认输，
   **绝不做半吊子替换**——`service/x.go` 若先吃掉扩展名会剩下「落点是 service/ 的方法」，
   既不是坐标也不是人话，而且已经没有违规词了，会**留在正文里**）；再改写；
   之后再查一遍：仍不合格（违规清零不了、汉字不足 `MIN_REMAIN=4`）就搬走。
4. **搬空的那一格不删**：缺口少一条，PM 就少看见一个缺口。留一句
   `技术细节见文末「研发参考」。`——不编内容，只指路。这是「信息不丢」在这一层的具体做法。

**代价（写在这里）**：改写只保证「没有违规词 + 句子还成句」，**不管读起来漂不漂亮**。
这一层是网，不是笔；正文的质量由提示词负责（§4 的那一对正例/反例）。
`旧路径 302 到新页并带 focus 参数。` 会变成 `旧路径自动跳转到新页并带定位设置项。`——
合规、可读、但不是最好的写法，最好的写法只能由模型给。

**为什么不是「退回重试」**：沿用第一轮的三条理由（重试是另一种提示词；不能因为一句话让整份
材料不出；搬正好是 owner 给的出口）。这一轮多一条：改写比重试便宜得多，且可测。

```
【技术词汇同样算违规】没有路径也算：下面这些词读者一样读不懂，一样会让 PM 翻页。
  · 网址参数：`?tab=rights&focus=ORDER_ID`（要写「自动切到「权益」标签并定位到刚点的那一条」）；

  建议：跳 /purchaseRecord?tab=rights&focus=ORDER_ID，命中项高亮 2 秒。
```

## 5. 可数指标：一个数，不是一句感觉

- `countProseHits(text, mode)` / `countHtmlBodyHits(html, mode)`：按**处**数算，不按种类算。
- **口径**：读者读到的正文文本节点——**跳过属性、`<script>`、`<style>`**；
  再加上标注那一档（`sanitizeAnno` 的 `raw` / `left`，那一档在上游按缺口档洗过）。
- **两个数**：`vocabHits` = 模型写出来的违规处数（**流水线的失误数**）；
  `vocabLeft` = 剥完还剩几处（应恒为 0）。三份材料各自的 stats 都带这两个字段
  （`InspectStats` / `ReviewStats` / `ComposeOutcome`）。
- **日志一行**（`reportVocab` → `stderr`，三个入口都调）：

```
[body-language] PAN-800 inspect hits=0 left=0 通过
```

- **为什么不抛**：本仓吃够了「整份不出」的苦（`types.ts` 的 `absent` 那一段）。违规词比
  「代码没读到」轻得多——读者少一句黑话，不是少一份材料。所以这一层**记账不拦**：
  数字进日志、进 stats，谁去修是人的决定；真正拦材料的是改写与搬走，它们已经尽力了。

### 5.1 一个必须说清的坑：`<script>` 里的 JSON

材料把 walkmap 原样塞在 `<script>var NODES = …</script>` 里，那段 JS 满是
`getElementById` / `setViewByNode` 这种驼峰名。**加上「裸驼峰算违规」之后，若不跳过 `<script>`，
`relocateProse` 会把页面脚本当正文删成残句——材料打开就是一片空白。**
所以 `relocateHtmlBody` 现在整块跳过 `<script>` / `<style>`（变异 M11 钉住它）。
反过来，正因为跳过，标注**必须在上游洗**（`assembleWalkmap` 里的 `sanitizeAnno`）——
否则缺口/建议那一档永远拦不到。

## 8. 还漏什么（具体，不含「未来可优化」）

1. **纯后端需求的走查会整份失败**（§6.1 实测）：一个页面节点都没有时
   `assembleWalkmap` 把节点挂到空页面，报「引用了不存在的页面「空」」。要修的是挂载规则
   （给这类流程一个「系统步骤」页或整份退化成清单材料）+ 提示词里写明「没有界面的流程怎么画」。
2. **改写不管质量**：`旧路径自动跳转到新页并带定位设置项。` 合规但不是最好的写法。
   这一层只能保证「没有违规词、还成句」；正文质量靠提示词那一对正例。
3. **`body` 档的领域豁免只有一条**（`接口`）。别的实现名词没有领域豁免，靠的是「不写进词表」
   （分页/导出/排序/筛选）。新词进不进表、要不要豁免，是一条产品判断，不是自动的。
4. **封闭表会漏**：`gap` 档的代码变量名只认 `tab/tabs/focus/param/params`。下一个材料里冒出
   `state`、`flag` 就漏——加一行 + 一条用例，不放宽成「所有英文单词」。
5. **顶部候选清单仍带坐标**（`1. \`src/pages/x.tsx\` ← …`）：那是 `CANDIDATES_LINE` 的既有措辞，
   是给 PM 拿去催研发的线索，这次**没动**（与第一轮同一条裁定）。所以成品整份扫是 20 处命中，
   指标口径是正文，不是成品全文。
6. **不能变成业务语言的东西**（写清楚，别假装能）：
   - `研发参考` 那一节**本来就该是**技术语言（仓、路径、行号、符号、受影响文件数）——它是给研发照着点开的；
   - PRD 自己的领域词：`分页`、`导出`、`排序`、`筛选`、`数电票`、`红冲`、`SKU`、`第三方接口`；
     它们在正文里是正名，只有在缺口/建议里才被拦（那些格是拍板用的，不是念术语用的）；
   - 品牌与产品名：`VIP`、`SVIP`、`iOS`、`iCloud`、`iPhone`、`WiFi`、`AppStore`；
   - 单证与编号类：`京东 ID`、`订单号`、`合作方编号`——它们是**用户/运营看到的值**，不是实现细节。
7. **`<title>` 与属性不扫**：`<head>` 里的标题、`class`/`onclick`/`data-*` 都跳过（那是页面的构造，
   改它会把页面改坏）。所以标题里的技术词仍然会漏。
